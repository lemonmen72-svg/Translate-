# ТЗ: Android-приложение офлайн-переводчик поверх медиа других приложений

## Идея проекта
Приложение для Android, которое запускается поверх других приложений (TikTok и
любые другие с видео/аудио), захватывает системный звук, распознаёт речь,
переводит её на русский и показывает субтитры (и опционально озвучивает)
поверх исходного приложения — с минимальной задержкой, полностью офлайн.

Причина делать своё, а не ставить готовое стороннее приложение-переводчик —
не доверять непонятным APK с широким доступом к системному аудио и не зависеть
от чужих серверов/подписок.

## Языки
- Распознаваемые языки (source): русский, английский, китайский, японский —
  список **фиксированный**, без автоопределения языка (язык выбирается
  заранее в настройках/на старте сессии).
- Целевой язык (target): **только русский**, всегда.
- Следствие: не нужен универсальный TTS на 4 языка — нужен ровно один
  качественный русский голос. Не нужен language identification (LID) —
  экономит один шаг в пайплайне.

## Архитектура пайплайна
1. **Захват системного аудио** — `AudioPlaybackCaptureConfiguration`
   (MediaProjection API, доступно с Android 10+). Позволяет перехватывать
   звук, который проигрывают другие приложения, если они не запретили это
   флагом `setAllowedCapturePolicy` (большинство приложений, включая TikTok,
   не запрещает).
2. **VAD (Voice Activity Detection)** — нарезка потока на завершённые фразы
   по паузам в речи. Кандидат: **Silero VAD** (ONNX, лёгкая, быстрая).
   Это главный рычаг субъективного снижения задержки — без VAD ASR будет
   резать фразы криво.
3. **ASR (распознавание речи)** — офлайн, с принудительным указанием языка
   (`forced language`), без автодетекции.
   - Кандидат 1: **whisper.cpp** (ggml-org/whisper.cpp) — есть готовые
     Android AAR-сборки с VAD-стримингом, квантованием, спекулятивным
     декодированием.
   - Кандидат 2: модели из проекта **RTranslator** (github.com/niedev/RTranslator)
     — Whisper-Small (244M), конвертированный в ONNX/int8 с KV-cache,
     специально оптимизированный под низкое потребление RAM на телефонах.
4. **Машинный перевод** — офлайн, всегда → русский.
   - Базовый вариант: **NLLB-Distilled-600M** (ONNX/int8), как в RTranslator.
   - Более качественный вариант (т.к. языков всего 3→1, а не 200): заменить
     на компактные билингвальные/специализированные модели под пары
     en→ru, zh→ru, ja→ru (в духе Helsinki-NLP/Opus-MT или
     дообученного/дистиллированного NLLB только под эти пары) — меньше
     параметров, быстрее инференс, выше точность за счёт отсутствия
     "размытия" на 200 языков. Особенно важно для ja→ru, где универсальные
     модели часто переводят через английский как посредник и теряют смысл.
   - Учитывать контекст предыдущих 1–2 переведённых фраз для связности
     длинных монологов (важно для местоимений, продолжения мысли).
5. **TTS (опционально, если нужна не только субтитровка, а озвучка)** —
   один голос, русский.
   - Кандидат: **Silero TTS** (github.com/snakers4/silero-models) — тот же
     коллектив, что делает Silero VAD, специально доводили русские голоса до
     естественного звучания, есть ONNX-версии, тот же рантайм (onnxruntime),
     что и у ASR/MT — не нужно тащить второй движок.
   - Альтернативы: Piper TTS (быстрее, но менее естественно звучит на
     русском), Kokoro-82M (лучше качество, но заметно тяжелее/медленнее —
     может добавить задержку).
6. **Оверлей поверх других приложений** — разрешение `SYSTEM_ALERT_WINDOW`,
   рисуется окно с субтитрами.
7. **Foreground Service** — связывает всё воедино, крутится в фоне.

## Ограничение задержки — что реалистично
- Нижняя граница задержки (от конца фразы до показа перевода) физически не
  устранима полностью — упирается в необходимость дождаться конца фразы
  (VAD) → распознать → перевести → вывести.
- Реалистичный ориентир при правильной оптимизации на современном флагмане
  (8GB+ RAM): **1.5–3 секунды**. Это сравнимо с Pixel Live Translate.
- Что реально снижает задержку и накладные расходы (но не саму физику
  пайплайна):
  - Фиксация языков → нет LID-шага.
  - Компактные модели под конкретные языковые пары вместо универсальных.
  - Настройка размера окна VAD и выбор размера модели ASR (tiny/base/small)
    — компромисс "быстрее, но менее точно" vs "медленнее, но качественнее"
    — стоит сделать переключаемым пользователем.

## Дополнительные технические задачи (важно для качества на реальном контенте)
- **Confidence score / фильтрация галлюцинаций** — Whisper иногда
  "галлюцинирует" на тишине/музыке/шуме; нужна проверка уверенности и логика
  "не показывать перевод, если ASR не уверен".
- **Разделение речи и фоновой музыки** — типичный TikTok-контент содержит
  музыкальный фон вместе с речью; рассмотреть лёгкий denoising/source
  separation (например, RNNoise) перед подачей в ASR.
- **Восстановление пунктуации** — проверить, добавляет ли выбранная сборка
  ASR знаки препинания, иначе перевод получится корявым.
- **Сведение громкости** — если используется TTS-озвучка поверх оригинала,
  нужно управлять громкостью исходной дорожки (AudioManager), чтобы не
  накладывались два голоса.
- **Энергопотребление и нагрев** — постоянная работа ASR+MT(+TTS) в фоне
  тяжела для CPU/NPU; предусмотреть энергосберегающий режим/троттлинг.
- **Ограничения Android 12+ на фоновые сервисы** — учитывать требования к
  foreground service (постоянное уведомление), а также агрессивное
  завершение фоновых процессов некоторыми прошивками (MIUI, One UI).

## UX
- Перетаскиваемый/сворачиваемый оверлей с субтитрами — с настройкой
  прозрачности и размера шрифта, не должен перекрывать важный контент.
- История/лог распознанного и переведённого текста — с возможностью
  прокрутить назад.
- Индикатор состояния (слушает / распознаёт / переводит), чтобы было
  понятно, что происходит, а не "зависло ли".
- Настройка выбора исходного языка перед запуском сессии перевода.
- Переключатель "скорость vs качество" (влияет на размер модели ASR/MT и
  окно VAD).

## Референсы для изучения кода/архитектуры
- github.com/niedev/RTranslator — готовый офлайн-переводчик для Android,
  использует Whisper + NLLB через ONNX Runtime, открытый код (Apache-2.0).
  Ближайший по духу существующий проект, полезно смотреть на реализацию
  пайплайна ASR→MT и на то, как оптимизированы модели под RAM/скорость.
- github.com/ggml-org/whisper.cpp — движок ASR, готовые Android-сборки.
- github.com/snakers4/silero-models — VAD и TTS для русского языка.

## Юридический момент
Захват системного аудио сторонних приложений (TikTok и т.п.) может нарушать
их условия использования (не закон, в большинстве юрисдикций для личного
использования это не проблема). Для приложения строго для собственного
использования это не критично. Не публиковать в Play Store без отдельной
проверки политики — Google может отклонить приложения с MediaProjection для
захвата чужого аудио.
